# OctoAcme Project Management Docs

This folder contains the shared project management guidance used by OctoAcme to initiate, plan, execute, release, and improve cross-functional work.

## Project management process overview

OctoAcme operates through a lightweight, repeatable project lifecycle that helps teams turn ideas into delivered outcomes with clarity and accountability.

1. Initiation — validate the problem, align stakeholders, and decide whether to invest in planning.
2. Planning — define scope, milestones, risks, ownership, and delivery approach.
3. Execution & tracking — run the work, monitor progress, manage blockers, and maintain quality.
4. Release & deployment — validate readiness, ship changes safely, and confirm impact.
5. Retrospective & continuous improvement — capture lessons learned and turn them into action.

The documents in this folder provide a shared reference for roles, responsibilities, communication, and delivery practices.

## Lifecycle in one view

- Initiation: confirm the need, define success goals, and align key stakeholders.
- Planning: set scope, milestones, dependencies, and ownership.
- Execution: build in short iterations, review progress, and resolve blockers early.
- Release: verify quality, communicate changes, and deploy with controls.
- Close: review outcomes, document lessons, and carry improvements into the next cycle.

## How to use these docs

- Start with the overview if you need a quick understanding of how OctoAcme runs projects.
- Use the initiation and planning docs when a new initiative is being considered or scoped.
- Use the execution and risk docs during delivery for tracking, communication, and escalation.
- Use the release and retrospective docs before launch and after milestones or incidents.
- Keep the project charter, backlog, risk register, and retrospectives updated so the process stays actionable and consistent.

## Team working principles

- Customer-first delivery and measurable outcomes
- Small, testable increments with clear ownership
- Transparent communication and consistent documentation
- Data-informed decisions and continuous improvement
- Cross-functional collaboration across product, engineering, QA, and stakeholders

These docs are intended to be a practical, shareable guide for running work consistently across teams and project types.
